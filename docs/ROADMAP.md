# Glass Inspection Studio — 활용 계획과 실사용 정제 계획

작성: 2026-11-25. 파일럿(합성 데이터 검증, JAI 카메라 연동, 실데이터 28장 라벨링·평가)이 끝난 시점을 기준으로 합니다.

---

## 0. 지금까지 확인된 사실

| 구분 | 상태 |
|---|---|
| 촬영 | JAI GOX-12405M-5GE (12MP Mono8). 웹 콘솔로 5 fps 안정 촬영 (Jumbo 9014 + 패킷 8192 B) |
| 데이터 | 실데이터 28장, 사용자 라벨 24개 (흑점 15, 기포 5, 명암·착색 3, 선형 파임 2). 정상 병 0개 |
| 결함 종류 | 흑점 / 기포 / 선형·부메랑형 내부 파임 / 미세 착색 (실물에서 확인) |
| 고전 CV | 흑점·기포는 recall 0.6~0.8이지만 오검출이 1MP당 수십~수백 개. 착색·선형 파임은 라벨이 너무 적어 판단 보류 |
| 주요 오검출원 | 고객 마커 잉크, 눈금·문자, 받침대·테이프·병 외곽선, 반사광 포화 |
| 한계 | 조명과 자세가 장마다 다름, 회전각 정보 없음, 정상 병 없음, NVIDIA GPU 없음 |

**결론:** 고전 CV는 후보 생성용으로는 쓸 수 있지만, 판정(오검출 제거)에는 학습 기반 2단 분류가 필요합니다. 그 판단을 확정하려면 촬영 조건을 고정한 데이터와 라벨이 더 필요합니다.

## 1. 활용 계획 (무엇을, 어떤 순서로)

### 단계 A — 데이터 확보 표준화 (1~3주)
목표: 비교 가능한 데이터를 만드는 것.

1. **촬영 조건 고정**
   - 백라이트 위치·거리, 노출·게인·Gamma를 정하고, 같은 값을 세션 메타데이터로 남깁니다.
   - 반사광 포화가 0.5% 이하가 되도록 조명 각도를 정합니다.
2. **병 단위 촬영 규칙**
   - 병 하나 = 세션 하나로 찍습니다.
   - 수동 회전 각도 간격(예: 30°)을 정하고, 같은 병을 2회 반복 촬영해 재현성을 확인합니다.
3. **샘플 확보**
   - 고객 NG 병은 전부 촬영합니다.
   - **정상 병을 최소 10~20개 요청**합니다. 이것이 없으면 오배출률을 계산할 수 없습니다.
4. **라벨링 가이드**
   - 클래스 정의와 예시 이미지를 정합니다.
   - 흑점은 점으로, 나머지는 결함에 딱 맞는 박스로 표시합니다.
   - 정상 영역(마커·눈금·외곽선)은 프레임마다 3~5개씩 표시합니다.
   - 목표 수량: 클래스마다 결함 50개 이상, 병 15개 이상.

산출물: 촬영 SOP 1장, 라벨링 가이드 1장, 표준 데이터셋 v1.

### 단계 B — 결함별 고전 CV 기준선 (1주, 단계 A 데이터 사용)
1. 결함 종류별 sweep을 실행해 추천 프리셋과 recall-오검출 곡선을 만듭니다(`tools/per_class_sweep.py`).
2. 병 단위 hold-out으로 과적합 여부를 확인합니다.
3. **결정 게이트 B:** 결함 종류마다 다음 중 하나로 분류합니다.
   - 고전 CV만으로 충분
   - 후보 생성 + 학습 분류기가 필요
   - 광학 개선이 먼저 필요

산출물: 결함별 기준선 보고서(현재 `PER_CLASS_REPORT.md` 형식).

### 단계 C — 학습 기반 판정 (2~4주)
1. **2단 구조:** 고전 CV 후보 → 결함 종류별 Patch CNN(32/128/256 px 문맥).
   - 마커·눈금·외곽선을 Hard negative로 학습합니다.
2. **U-Net 비교:** 결함 종류별 채널로 학습하고, 미확인 영역은 Loss에서 제외합니다.
3. **같은 테스트 병으로 비교합니다.** 비교 대상은 고전 CV, 2단 CNN, U-Net입니다.
4. **Active Learning:** 모델 후보를 웹 라벨링 화면에서 승인·거절 → 다시 학습. 2~3회 반복합니다.
5. GPU가 필요하면 이 단계에서 확보합니다. CPU에서 12MP U-Net 추론은 프레임당 약 2초입니다.

**결정 게이트 C:** 결함별 목표 recall(예: 흑점 0.95)을 만족하는 오검출 수준을 확인하고, 양산형 구조(단일 모델 / 2단)를 결정합니다.

### 단계 D — 광학계·장비 결정 지원 (단계 B와 병행 가능)
1. **해상도:** 결함 크기 분포(흑점 2~10 px)로 필요한 mm/px와 렌즈 배율의 여유를 계산합니다.
2. **회전 스테이지 연동:**
   - CoPick의 RC/VC/FIN 핸드셰이크(Modbus) 규약을 재사용해, 스테이지가 위치를 잡을 때마다 자동 촬영합니다.
   - Angular Visibility 분석으로 필요한 촬영 각도 간격을 정하고, 거기서 fps와 회전 속도를 산출합니다.
3. **네트워크:** 5GbE NIC를 확보하면 카메라 본래 프레임률(8.4 fps 이상)을 쓸 수 있습니다.
4. **조명 비교:** 같은 병을 조명 A/B로 촬영해, 결함별 SNR 차이를 이 도구로 정량 비교합니다.

### 단계 E — 양산 검증으로 이행 (정상 병 확보 후)
- 정상 병 기준 오배출률, 병 단위 판정, 처리 시간(GPU, ONNX/TensorRT)을 측정합니다.
- 고객 규격(Dust·Scratch 허용 기준 등)을 반영한 최종 판정 규칙을 정합니다.

### 보고 체계
- 단계마다 보고서 1부를 냅니다. 내용은 데이터 현황, 결함별 결과표, 예시 이미지, 한계, 다음 결정 사항입니다.
- 모든 수치에는 "라벨 수", "정상 병 유무", "촬영 조건"을 함께 적습니다.

## 2. 실사용 정제 계획 (프로그램을 쓸 수 있는 상태로)

현재는 기능이 세 군데로 흩어져 있습니다.
- 데스크톱 GUI
- 웹 카메라 콘솔
- 웹 라벨링 화면

여기에 프로젝트 경로를 CLI 인자로 넘겨야 하고, 분석·보고서는 스크립트로만 돌릴 수 있습니다. 실제 사용 흐름(촬영 → 라벨링 → 분석 → 보고서)을 **한 화면**에서 할 수 있게 정리합니다.

### R1. 통합 웹 스튜디오 (핵심) — 1차 구현 완료 (2026-11-25)
* 구현된 것:
  * `GlassInspectionStudio.cmd`
  * 프로젝트·촬영·라벨링·분석·보고서 탭
  * 낮은 우선순위의 별도 프로세스 작업과 로그
  * 열 때 DB 자동 백업
  * 카메라 설정의 프로젝트 저장
* 남은 것:
  * 검출기 후보를 라벨링 화면에 제안으로 표시 (R3)
  * 미검토 프레임 필터
  * 분석 결과의 곡선 그래프
- 실행: 파일 하나(`GlassInspectionStudio.cmd`)를 실행하면 서버가 뜨고 브라우저가 열립니다.
- 탭 구성:
  1. **프로젝트:** 목록·생성·열기, 병/세션 트리, 데이터 가져오기(폴더·zip), 메타데이터 편집
  2. **촬영:** 현재 카메라 콘솔. 카메라 설정 프로필을 프로젝트에 저장
  3. **라벨링:** 현재 라벨링 화면 + 미검토 프레임 필터, 클래스 가이드 패널
  4. **분석:** 검출기 실행, 결함별 sweep, 진행률 표시, 결과표·곡선·예시 이미지 보기
  5. **보고서:** 버튼 하나로 HTML 보고서 생성(데이터 현황·결과표·예시 crop)
- 카메라는 촬영 탭을 열 때만 연결하고, 다른 프로그램과 충돌하면 명확하게 안내합니다.
- 무거운 분석은 낮은 우선순위의 별도 프로세스로 돌려, 촬영과 충돌하지 않게 합니다.

### R2. 안정성·데이터 보호
- 프로젝트 DB를 자동 백업합니다(열 때, 일정 간격).
- 서버·카메라·분석 로그를 파일로 남기고, 화면에 오류를 표시합니다.
- 라벨 export/import(JSON)로 다른 PC와 주고받을 수 있게 합니다.

### R3. 라벨링 생산성
- 프레임 필터: 미검토 / 결함 있음 / AI 후보 있음
- 검출기 후보를 회색 제안으로 표시하고, 클릭 한 번으로 승인 또는 정상 처리
- 폴리곤 도구, 라벨 복사(인접 프레임), 클래스별 개수 현황판

### R4. 배포
- 깨끗한 PC에서 `setup.ps1`이 처음부터 동작하는지 검증합니다.
- 사용자 가이드를 촬영·라벨링·분석 위주로 다시 씁니다.
- 버전 표기와 변경 이력을 둡니다.

### 데스크톱 GUI 처리
- 웹 스튜디오를 기본으로 합니다.
- 데스크톱 GUI는 고급 기능(학습 설정, 상세 평가) 용도로 유지하고, 새 기능은 웹에 먼저 넣습니다.

### 우선순위 제안
1. R1의 프로젝트·라벨링·분석 탭 + R2 백업 → 바로 단계 A·B를 진행할 수 있음
2. R1의 보고서 탭 + R3 제안 승인 → 단계 C의 Active Learning 준비
3. R4 배포 정리
